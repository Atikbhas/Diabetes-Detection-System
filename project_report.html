Data Flow Diagram
User Side Data Flow Diagram
Admin Side Data Flow Diagram
Admin DFD Flow:
1. Admin logs in via `/login` using admin credentials.
2. System checks `is_admin` flag in users table.
3. Grants access to protected `/admin` dashboard.
4. Admin monitors system totals, filters prediction logs, manages user accounts, and reviews feedback submissions.
Page 7
E-R Diagram

An Entity Relationship Diagram (ERD) graphically illustrates the database entities (`users`, `predictions`, `feedback`, `contact_submissions`) and relationships between them.

Entities & Relationships:

• USERS Table (1 to Many) ──► PREDICTIONS Table
• USERS Attributes: id (PK), username, email, password_hash, is_admin, created_at
• PREDICTIONS Attributes: id (PK), user_id (FK), pregnancies, glucose, blood_pressure, skin_thickness, insulin, bmi, diabetes_pedigree, age, result, probability, created_at
• FEEDBACK Attributes: id (PK), name, email, rating, message, created_at
• CONTACT_SUBMISSIONS Attributes: id (PK), name, email, subject, message, created_at

Software Development Life Cycle
  • Planning and Requirement Analysis: Defined system goals, collected physiological parameter specs, and outlined guest assessment flows.
  • Design: Created responsive Bootstrap layout, custom medical styling, database schema, and chart rendering pipeline.
  • Development: Coded Flask application backend, Scikit-learn Random Forest ML predictor, and ReportLab PDF builder.
  • Testing: Performed comprehensive unit tests, authentication checks, guest form redirects, and PDF generation tests.
  • Deployment: Configured virtual environment, SQLite initializers, and local web app deployment.
  • Maintenance: Ongoing bug fixes, UI styling refinements, and version control management via GitHub.
